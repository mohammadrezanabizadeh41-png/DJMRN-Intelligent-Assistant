### Minimal trusted boundary required regardless of UI

**Source-derived fact:** current CAP-006 accepts caller-selected paths and returns deterministic original file/line/text/hash under bounded conditions; previous Windows user-run technical test passed on two copies, but there is **no separate user-approved manifest/permission gate** and no standalone chat interface.

**Needed but NOT YET IMPLEMENTED:** trusted executor binds a 1–2-file manifest approved out-of-band to opaque file IDs, validates canonical paths and typed query, restricts tool name/output/time/size and denies all file/folder/third-file/write/shell/network behavior by default. UI approval is not equivalent to trusted backend gate; `readOnlyHint` metadata cannot enforce authorization. Model may summarize text separately but must not forge the displayed source file, line or hash; cancellation/crash/hardlink/symlink/junction/race are tests/engineering challenges. An ordinary same-user process gate is not a general OS sandbox.
