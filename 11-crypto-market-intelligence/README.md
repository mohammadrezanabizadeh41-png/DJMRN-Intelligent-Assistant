## 3. یافته‌های Work (گزارش ارائه‌شده توسط کاربر، 2026-11-06)
پژوهش Work مسیر مشروط **Freqtrade + FreqUI + لایه پژوهش سبک + SQLite + AI ابری اختیاری** را برای حلقه زنده پیشنهاد داده است؛ این **انتخاب قطعی نیست**، چون هسته Freqtrade به‌تنهایی تحلیلگر بنیادی/خبری خودکار و شکارچی فرصت نیست.
- Freqtrade: داده کریپتو، فهرست پویا، اندیکاتور، بک‌تست، dry-run و پایش؛ FreqUI نمایش وضعیت. امکان RemotePairList و کانال WebSocket analyzed_df به‌عنوان گزینه اتصال، نیازمند آزمون نسخه و محیط.
- لایه پژوهش پیشنهادی، محصول آماده مستقل نیست؛ باید فقط برای شکاف اثبات‌شده نوشته شود: هویت دارایی، کیفیت و تازگی داده، خبر، بنیادی، تحلیل ترکیبی، رتبه‌بندی، هشدار و حافظه.
- SQLite برای state پژوهش/هشدار؛ هسته مالک داده معاملاتی آزمایشی خودش؛ لایه پژوهش مالک شواهد و تحلیل. مدل زبانی فقط از شواهد موجود تحلیل/توضیح دهد؛ محاسبات عددی و ریسک deterministic و قابل آزمون باشند.
- مسیرهای رقیب: Superalgos (یکپارچه بصری، اما هوشمندی بنیادی آماده تأیید نشده)، Fincept Terminal (ترمینال چندبازاری؛ پوشش واقعی خودکار باید بررسی شود)، Gunbot Quant (شرایط مجوز/قیمت باید بررسی شود)، OctoBot، و مسیر سفارشی CCXT + Backtesting.py + SQLite.
- محدودیت‌های گزارش Work: RAM واقعی UNKNOWN؛ Binance از محیط پژوهش HTTP 451، Kraken timeout، Coinbase historical پاسخ داده ولی سازگاری Freqtrade نامعلوم؛ اینها آزمون لپ‌تاپ نیستند. CoinGecko Public و Demo سهمیه متفاوت دارند؛ DefiLlama/Coin Metrics Community محدودیت داده؛ RSS خبر تأخیر دارد؛ Alpaca Basic پوشش محدود IEX و Massive Basic داده EOD؛ پوشش زنده رایگان همه بازارها اثبات نشده.
- آزمون‌های backtest باید کارمزد، لغزش، spread، gap و داده تاریخی point-in-time را لحاظ کنند؛ خبر/بنیادی امروز را نمی‌توان به گذشته تزریق کرد. برای خبر و بنیادی از امروز first_seen ذخیره شود؛ داده‌های vintage مثل ALFRED برای آزمون تاریخی مهم‌اند.
- پیشنهاد Work: شروع با BTC ETH SOL AVAX NEAR SUI APT LINK AAVE UNI مشروط به پشتیبانی منبع، سپس ۱۰→۲۵→۶۰→۱۰۰.
- اهداف آزمایشی پیشنهادی (نه نتایج واقعی): p95 RAM حدود ۳.۵GB، peak ≤۴GB، پوشش کندل ≥۹۹٪ در بازه معتبر، تأخیر پردازش داخلی p95 ≤۲ ثانیه، بازیابی هدف ≤۵ دقیقه پس از backfill، منشأ قابل ردیابی برای همه خروجی‌ها، صفر سفارش واقعی.

### مراحل به ترتیب، با خروجی و شرط عبور
**P0 — شروع از نرم‌افزار، نه بنچمارک سخت‌افزار.** نخست نسخه/README/license/install رسمی Freqtrade و گزینه ساده CCXT را بازبینی کن؛ سپس *طرح نصب ایزوله و قابل حذف* برای ویندوز آماده کن. پیش از اجرای نصب روی رایانه، مجوز مشخص کاربر بگیر. هیچ Docker/WSL/رابط گرافیکی را پیش‌فرض نکن؛ روش کم‌وابستگی و سازگار با Windows را انتخاب کن. VPN موجود کاربر باید در هنگام اتصال واقعی آزموده شود؛ پراکسی/گواهی/شبکه را خودسرانه تغییر نده.

**P1 — اولین حلقه واقعی داده صرافی.** برنامه منتخب را نصب و در محیط ایزوله اجرا کن؛ بدون API key معاملاتی، بدون سفارش و بدون live trading. از منبع عمومی صرافی، تاریخچه و داده جدید ۳ تا ۱۰ دارایی دریافت و در فایل/SQLite با source/time/asset/exchange/quote/candle ذخیره کن؛ تکرارپذیری، خطا، قطع شبکه، rate limit و تازگی داده را بسنج. اگر Freqtrade متناسب نبود، به CCXT یا دریافت مستقیم رسمی تغییر مسیر بده. **خروجی:** یک فرمان شروع، یک فرمان توقف، یک فایل داده معتبر، یک گزارش خطا.

**P2 — پژوهش بنیادی و رقابتی مستقل.** onchain-research-desk و منابع رسمی/عمومی داده را جداگانه آزمایش کن؛ ۲–۳ پروژه هم‌حوزه را با TVL، fees/revenue، ارزش بازار/FDV، unlock، نقدینگی، کاربران و نسبت ارزش اقتصادی توکن به پروتکل مقایسه کن. داده ناموجود را UNKNOWN بگذار؛ provenance و timestamp ضروری. داده تاریخی بنیادی بدون زمان انتشار واقعی در backtest استفاده نشود (no look-ahead). **خروجی:** یک گزارش بنیادی و رقابتی مستند برای دارایی‌های نمونه.

**P3 — موتور کمی و آزمون معتبر.** یک baseline ساده + مدل آماری/ML سبک با داده point-in-time مقایسه کن؛ آموزش/اعتبارسنجی زمانی و walk-forward، کارمزد/لغزش/نقدینگی، عدم leakage، نرخ هشدار کاذب و بازده تعدیل‌شده با ریسک. یک مدل مشترک یا گروهی را قبل از مدل اختصاصی هر ارز آزمایش کن. مدل‌ها ذخیره و هنگام داده جدید inference شوند؛ retraining جدا و دوره‌ای است، نه هر دو دقیقه. **خروجی:** گزارش خارج از نمونه و دلایل رد/قبول مدل؛ هیچ تضمین سود.

**P4 — AI و ادغام شواهد.** SignalDesk را مستقل آزمایش کن؛ در صورت تناسب فقط خروجی/ماژول آن را با قرارداد داده روشن متصل کن. اگر نیاز واقعی بود یک تحلیلگر AI با شواهد بنیادی/خبر/رقبا و خروجی مدل‌های کمی فراخوانی کن؛ مدل زبانی حق اختراع عدد/منبع/قیمت ندارد. محاسبه حد ابطال، نسبت بازده به ریسک و کنترل محدودیت‌ها با کد قطعی انجام شود. **خروجی:** گزارش «فرصت / صبر / عدم ورود / داده ناکافی» شامل thesis، ضدشواهد، ورود احتمالی، اهداف، ابطال، افق، هزینه و زمان انقضا.

**P5 — پایش بی‌وقفه و هشدار بدون UI.** یک فرایند سبک پس‌زمینه و SQLite، به‌روزرسانی افزایشی، صف رویدادها، dedup، cooldown، retry/backoff، بازیابی پس از قطع VPN/شبکه، logging و هشدار متنی؛ به‌جای تحلیل سنگین همه ۱۰۰ دارایی در هر چرخه. **خروجی:** اجرای واقعی با شروع/توقف روشن، بدون سفارش، با آزمون قطعی قطع و وصل شبکه.

**P6 — مقیاس و کشف فرصت جدید.** ۱۰→۲۵→۶۰→۱۰۰ دارایی فقط پس از کیفیت و منابع قابل قبول؛ کشف توکن جدید با کنترل هویت قرارداد، نقدینگی، پوشش داده، ریسک rug/scam و فهرست‌پذیری در صرافی. مقیاس با مشاهده واقعی RAM/CPU/تأخیر/کیفیت/هزینه، نه حدس اولیه.

**P7 — تصمیم سرمایه‌گذاری واقعی فقط با مجوز جدید.** حتی پس از بک‌تست و paper tracking، هیچ API key معاملاتی، سفارش، انتقال وجه یا اجرای زنده بدون پیشنهاد امنیتی/ریسکی و approval صریح.

### قرارداد اتصال اجزا — ابتدا ساده
یک فرایند Python ماژولار با فایل/SQLite و توابع/CLI ابزارهای منتخب؛ تا وقتی نیاز اثبات نشده API server، microservice، چند agent یا registry جدید نساز. هر تحلیل شامل: asset identity (chain/contract/exchange pair)، timestamp، source، quality/staleness، raw evidence، model version، assumptions، confidence calibration، risk inputs، output، outcome و failure reason. raw data مرجع است؛ خلاصه AI مرجع داده نیست. هر منبع داده فقط یک مالک canonical دارد. در صورت استفاده از برنامه ثالث، از API/CLI/export رسمی استفاده شود، نه کپی نامجاز کد.
