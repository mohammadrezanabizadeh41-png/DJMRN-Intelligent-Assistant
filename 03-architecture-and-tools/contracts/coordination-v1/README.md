# DJMRN Coordination Contract v1.0 — Design Baseline

**وضعیت:** بسته کاملِ قرارداد پیشنهادی برای بررسی و شروع ساخت؛ **نه محصول نصب‌شده، نه معماری مصوب اجرایی، نه تایید رسمی انطباق A2A/MCP/AG-UI**.

## فایل‌ها و کاربرد

| فایل | مصرف‌کننده |
|---|---|
| `DJMRN-Coordination-Contract-v1.0.md` | سند مرجع قواعد معماری هسته مرکزی، تخصص‌ها، پیام‌ها، وضعیت، دانش و مجوز |
| `manifest.v1.json` | فهرست قراردادهای آماده انتخاب‌شده، مالکیت‌های داده و الزام‌های اتصال |
| `schemas/hub-record.schema.json` | اعتبارسنجی انواع رکوردهای داخلی HUB (نه جایگزین JSON Schema رسمی A2A/MCP) |
| `openapi/hub.openapi.json` | تعریف اولیه API داخلی هسته؛ هنوز سرور واقعی وجود ندارد |
| `state-transitions.v1.json` | انتقال‌های مجاز وضعیت task، نیازمند اجرای transaction و policy |
| `capability-registry.example.json` | نمونه رجیستری تخصص‌ها؛ فقط search_specialist حق اجرای وب به نمایندگی دیگران |
| `model-policy.example.json` | قواعد مدل‌های free-first در OmniRoute؛ هیچ مدل/کلید حسابی به فایل افزوده نشده |
| `examples/valid-records.json` | نمونه رکوردهای درخواست، وظیفه، dispatch، منبع، نتیجه، تأیید و audit |
| `tests/validate_contract.py` | آزمون آفلاین ساختاری JSON Schema و اعتبار بعضی ارجاع‌های OpenAPI |
| `VALIDATION-REPORT.md` | شرح دقیق موارد پاس و موارد هنوز آزمون‌نشده |

## نحوه استفاده در ادامه پروژه

۱. در مخزن **DJMRN-Intelligent-Assistant**، این فایل‌ها مرجع نسخه‌دار کد نویسی آداپترها و هسته خواهند بود. قرارداد قدیمی OSCP v0.1 و تحقیق‌های 001/002/003 همچنان حفظ می‌شوند.

۲. اولین برنامه عملی: رابط فارسی یا ورودی تست → Task Ledger در Hub → CAP-006 فقط‌خواندنی → Evidence → ذخیرهٔ نتیجه/بازیابی. **به عامل همیشه‌فعال، Gmail یا مدل ابری برای این PoC نیاز نیست.**

۳. پس از PASS شدن PoC، Specialist جست‌وجو با workflow ثبت‌شونده و Knowledge Service اضافه می‌شوند؛ بعد Gmail read-only و سپس در صورت تأیید draft/ارسال، با هر عمل مجوز جداگانه.

۴. هنگام افزودن یک دستیار جدید، `Capability Registry` و Adapter قرارداد خوانده می‌شوند، نه اینکه به تک‌تک دستیارهای موجود کد جدید نوشته شود.

۵. هنگام افزودن سرویس مستقل خارج از فرایند، A2A/MCP/AG-UI با SDK و مشخصات نسخه‌پین‌شده استفاده می‌شوند. هیچ‌کدام جای مرجع عملیات پایدار مرکزی و کنترل سیاست را نمی‌گیرند.

## آزمون آفلاین ساختاری

در محیطی که `jsonschema` نصب است، از ریشه این بسته:

```bash
python tests/validate_contract.py
```

این تست در محیط تولید فایل اجرا شد و نمونه‌های معتبر/نامعتبر را بر اساس Schema بررسی کرد. **تست پیاده‌سازی Windows، A2A TCK، MCP interop، OpenAPI validator مستقل، امنیت، پروتکل OAuth، سرویس Gmail، crash recovery یا انطباق مدل‌های OmniRoute اجرا نشده‌اند** و نتیجه‌ای برای آنها ادعا نمی‌شود.

**منبع استانداردهای مورد استفاده:** لینک‌های مستندات رسمی در سند اصلی و Manifest v0.1. **تمام داده‌های example مصنوعی‌اند؛ نشانی example.org واقعی نیست و فایل شامل کلید/API token یا متن ایمیل واقعی نیست.**
