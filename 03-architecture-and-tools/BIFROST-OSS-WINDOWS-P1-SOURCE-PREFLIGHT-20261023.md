## Key findings and corrections to previous DJMRN assumptions
1. **P1 changes Windows suitability from merely UNKNOWN to SOURCE-VERIFIED NATIVE PATH**. Because tagged NPX launcher explicitly maps win32 x64 and build script compiles Windows/amd64, the lightweight native **candidate** is now credible. **No actual binary signature, hash, runtime performance or install verification**; don't upgrade to WINDOWS-PASS.
2. **Bifrost has a real built-in Beta Complexity Router** for `SIMPLE|MEDIUM|COMPLEX`, confirmed both tagged documentation and source; earlier suggestion an external classifier would automatically be needed is OBSOLETE. Built-in classification itself costs another inference/embedding request and is not a substitute for deterministic free-only admission and reserve policy. It is permitted as a FUTURE optional component only after version-specific mock+cost test.
3. **Critical default security caveat**: newly started UI/API can be unprotected until admin authentication is configured; even loopback-only requires an explicit setup plan. **Never** use `-host 0.0.0.0` for first DJMRN trial. UI config and inference auth are separate settings; virtual-key restrictions are another independent enforcement layer.
4. **Cross-provider free models differ in names and capabilities.** Static `allowed_models` and simple aliases may not automatically ensure that `djmrn-reasoning` chooses the correct provider-specific DIFFERENT model ID on a real 429. Use validated CEL rules or explicit fallback `provider/model` mapping, and test that no protected higher-tier route leaks.
5. **Source release ≠ download.** Repo release tag v2.3.2 no GitHub asset in public release metadata, and NPX package tag/wrapper can differ. Before any user-approved test, independently verify download URL+HTTPS+checksum/signature, actual Node requirements and bind config without running the unsigned binary automatically.
