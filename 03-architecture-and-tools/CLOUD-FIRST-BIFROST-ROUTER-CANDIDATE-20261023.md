## Why Maxim for CENTRAL SHARED ROUTER, not free-only catalog champion
Core practical requirement is **one stable OpenAI-compatible HTTP endpoint** for Jan/Goose/future Persian GUI and multiple registered providers, behind fixed model aliases and a configurable fallback order. The vendor [README](https://github.com/maximhq/bifrost) identifies Bifrost as Go gateway to 23+ providers. [Official retry/fallback docs](https://docs.getbifrost.ai/features/retries-and-fallbacks) describe providers/keys and automatic per-request retry/fallback across providers on eligible 429/quota/errors, with bounded retries and configurable routing. [Official May 2026 release docs](https://docs.getbifrost.ai/changelogs/v1.5.0) describe alias, per-model/virtual-key allowlists, pricing/budget and routing features; **version and OSS/Enterprise scope must be pinned and checked before deployment**. [October release list](https://github.com/maximhq/bifrost/releases) shows HTTP transport v2.3.2; GitHub /releases/latest identifies a separate `ent-v2.3.2-base` tag and MUST NOT be silently treated as OSS binary/version. NPX launcher and Docker are documented, Windows runtime metrics/compatibility of selected exact OSS artifact not observed.

Comparative judgment based on reviewed code and sources:
- `pauljones0/freellmpool_sandbox` fork/source v0.14.7: strongest specific **SQLite shared allowance** evidence (`reserve/settle/observe_remaining` and unit tests), but setup documented with shell/systemd and Unix paths; Windows native service/autostart/rollback, broader protocol and actual multi-app resilience not measured. Good alternate for later mock-only quota engine if Bifrost fails unmet strict quota requirement. Do NOT install it alongside Bifrost by default.
- `freelm`: lighter SDK/optional server, shared concurrent durable daily quota accounting weaker/unproven than fork; keyless, hedging, reset behavior require guard.
- `LiteLLM Proxy`: broad provider support, virtual keys, fallback; local budget/fallback do not imply upstream free quota truth; more admin/storage complexity for small Windows laptop. [LiteLLM budget docs](https://docs.litellm.ai/docs/proxy/users) document zero-price models exempt from budget checks and fallback between model limits; verify version.
- `boelabs/bifrost` is a **different** more infrastructure-heavy Bun/Redis/Postgres pre-1.0 product, not substitute for Maxim.

## Desired routing contract and non-misleading continuity
Target one locally bound authenticated loopback OpenAI-compatible HTTP base URL (documentation examples `http://127.0.0.1:8080/v1`, **not yet active**) and one DJMRN *logical model alias* (e.g. `djmrn-chat-free`; **proposed, not verified to be accepted unchanged by chosen binary**). Stable client base URL = clients don't reconfigure per provider. Admin retains private provider keys; clients use restricted virtual key if the exact OSS build supports it. No direct access by cloud models to Windows tools or secrets. Failover chain contains ONLY individually confirmed API free models with capabilities sufficient for user's Persian/chat/coding/tool request.

Distinguish:
1. Gateway **connection availability** = localhost endpoint running.
2. **Request-level fallback** = Bifrost tries eligible next provider on errors before returning failure.
3. **Exact account daily remaining/reset** = NOT proven universal auto detection; 429 can mean minute rather than day; Bifrost budget/local limit != upstream entitlement.
4. **Transparent mid-stream continuation** = NOT guaranteed after first streamed token/side-effect; callers need explicit error handling and completed-stream status.
5. **All routes exhausted** = return controlled unavailable/quota message; can't guarantee successful reply without at least one healthy eligible route.
6. **Paid risk** = neither price label nor router budget can guarantee hard-zero external charge. Allowlist routes, unknown price DENY, disabled provider auto-topup/payment/paid fallbacks and provider-enforced caps where supported.
