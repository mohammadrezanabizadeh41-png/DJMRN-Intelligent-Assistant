## Scope-supported conclusion (report, not project approval)
WA0001 compares five sequencing approaches. For a first manually run, read-only, deterministic capability it recommends **B then E**: define a *small conceptual input/output/permission/result contract*, build one useful no-Agent capability, and add persistence/queue/model/resource manager only in response to observable needs. Central resource management may be needed *before* automated concurrent heavy workloads, shared model leases, owned-child safety, unattended recovery and external side effects. No product/language/engine is selected. Suggested first V0: Persian normalized text/source-grounded lookup and extraction in 2–3 expressly permitted non-sensitive local documents; no model/server/online account. Exact V0 use case not yet user-approved.

Stable conceptual fields: `task_id, capability, input_ref, owner, permission_scope, result_ref, status, error, receipt, cancellation/deadline`; no physical DB, daemon, dispatcher or Agent required on V0.

## Accepted insight / remaining uncertainties
**Useful as a conditional design direction:** avoid prematurely building a permanent resource manager, use a stable task boundary, keep authority independent of models, and define triggers for escalation. **Not proven:** actual time-to-first-useful-result, memory savings, best language/tool, model unload on hardware, legal/cloud access, safe unattended recovery, preferred first vertical.

The original research scope concerns architecture **sequence**, not full implementation readiness.
