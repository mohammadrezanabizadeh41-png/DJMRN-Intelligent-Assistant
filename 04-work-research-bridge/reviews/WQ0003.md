## 3. Accepted technical learning, caveats and unresolved choices

**Accepted conditional pattern:** `Chat UI → model/intent interpretation → narrowly exposed tool (e.g. MCP stdio) → trusted approved allowlist/source mapping → existing CAP-006 deterministic lookup → cited Persian chat response`. Model cannot provide shell commands, arbitrary file paths, source grants or `approved=true`. Initial tool has one active call and fails closed for out-of-scope source, stale content, denied approval or offline local host. A host-agnostic adapter contract is desirable; don't reimplement CAP-006, multiple models/Agents or a central runtime today.

**Product candidates, NOT adopted:**
- **Jan Desktop v0.8.7 + one narrow MCP stdio tool** is Work's *first conditional candidate only if a separate private/local chat surface is acceptable*. Official release validates the new Shell OFF feature **and its default ON**. Test using a real host/model with **all general-purpose Shell/Web/File extras disabled**, Allow All permissions off, and explicit per-call approvals. The latest official docs do not themselves prove device RAM, Persian model tool calling, data egress, Windows bridge security or clean tool isolation; those are gating falsifiers.
- **Cherry Studio v2.1.7** remains a possible alternative client with its own extra tools/autoapproval audit. No proven lower RAM, safer default, user entitlement or tested Windows integration. If Jan fails, Cherry is a candidate, not an automatic fallback to install.
- **ChatGPT Desktop local MCP** is a documented architecture option, especially if user insists on sending commands *inside ChatGPT*. But *this conversation's GitHub connector does not make local Windows files reachable*. Product/version/plan availability, auth, permission scoping, supported Windows installation context and data-transfer consent require real checks first; `not verified` rather than `impossible` or `already working`.
- **ChatGPT web Secure MCP Tunnel** is a distinct remote API/Platform/workspace/key/region/cost case, not free-by-default or automatic. Official API country list omits Iran; **DO NOT ACTIVATE** unless legal eligibility, permissions and costs are independently established. No circumvention assumption.
- Native minimal UI or other hosts remain technically possible for privacy/constraints, but a narrow deterministic parser chat is **not** the full intelligent assistant experience. Existing n8n/goose/5ire/full-agent framework's broader capabilities do not justify their added permission surface for a one-lookup pilot.
- MCP stdio removes need for an exposed public port in a local-child process design but **does not guarantee sandbox, isolation from host filesystem, or no data egress by an LLM host**. Caller-based approval is only a meaningful security boundary if implemented/enforced outside the model and demonstrably bound to the actual call. Effective grants/OS permissions must be scoped.
