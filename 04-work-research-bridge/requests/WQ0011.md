## 5 — Required target: one light capability-aware Cloud-first inference layer

Describe a **single, stable, authenticated loopback API endpoint** for DJMRN's multiple chat surfaces/agents/programs (including potential Python client, Jan, Goose where actually compatible). Remote models generate textual advice/tool-call **proposals only**; **local trusted executor** retains source-of-truth, exact-file allowlist, anti-TOCTOU guard when proven, policy approvals and actual execution. Keep model routing/token spend isolated from permission decisions.

A common `RequestCapabilityContract`: app/assistant ID, tenant/budget bucket, task class, prompt & sensitive-data class, required modalities, tool-calling type/format/schema, context token budget, response format, response validation, model allowlist, minimum quality, max latency/cost/free-only, safe stop. Compare candidate model capabilities; never silently downgrade to a model without the user's required tool, language, JSON schema, confidentiality/region or reasoning baseline. **Gracefully fail closed** with informative `UNAVAILABLE_OR_QUOTA_EXHAUSTED` if none qualifies.

Explicit resilience finite-state model: `Available`, `RateLimited`, `QuotaExhausted`, `TemporarilyUnavailable`, `AuthenticationError`, `BudgetExhausted`, `Disabled`, optional `UnknownHealth`. Differentiate:
- `429`: may be short-term RPM/TPM or daily cap; parse provider-specific headers, not categorically 'free tokens used up'; obey `Retry-After` where available.
- `401/403`: credentials, account rights, regional restrictions; **do not blindly rotate credentials** or retry/circumvent region/terms.
- `402/insufficient credits`: hard stop for paid/zero budget unless approved reserve exists.
- `5xx/timeouts/disconnect`: bounded retries/backoff/jitter/circuit breaker with capped cross-provider fallback; no retry storms or multiple requests repeatedly charged.
- Provider reports quota reset: store actual authoritative reset timestamp/timezone; where unknown use conservative bounded probing, never fabricate a 'daily midnight' reset or intentionally ping to evade limits.
- Re-entry of a recovered provider after confirmed cooldown / health check and budget eligibility. Recalculate estimated input+output cost with **pre-send hard caps** and usage receipt after response; classify UNKNOWN cost as deny, not 'free'.
- Streaming interrupts: detect partial completion and tell user, explicitly decide if recreating response is safe; do not implicitly assume stateful conversation contexts, provider conversation IDs and tools survive model/provider switches. Support versioned prompt/context snapshots, redacted usage/audit logs.

**Safety-critical distinction:** a completed/pending **external action** (PowerShell/file edit/email/payment/DB mutation) must not replay just because the LLM failed over, timed out or duplicated a tool call. Use request IDs, durable action receipts, idempotency keys where supported, human approval and transactional state checks outside the model routing layer. LLM text retry is NOT tool retry. On ambiguity (request may have reached provider/tool), stop and reconcile instead of repeated state-changing actions.
