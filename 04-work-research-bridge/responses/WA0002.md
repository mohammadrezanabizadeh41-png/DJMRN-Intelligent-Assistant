## پاسخ تصمیم‌محور

**پیشنهاد مشروط اول: CAP-006 را برای یک سؤال واقعیِ تکرارشونده به یک گردش‌کار سندیِ قابل‌استفاده برسانید، بدون افزایش دامنهٔ موتور.** کاربر یک مجموعهٔ کوچک و ثابت از نسخه‌های غیرحساس اسناد و یک جست‌وجوی مشخص را انتخاب کند؛ خروجی، یک گزارش خوانای فارسی همراه با نتیجهٔ JSON و مسیر/شمارهٔ خط/SHA256 باشد. نخست با CLI موجود بررسی شود آیا همین مسیر کافی است؛ تنها اگر ورود فرمان یا خواندن JSON مانع واقعی استفاده است، یک ورودی ساده و نمایش‌دهندهٔ کوچک اضافه شود. رابط گرافیکی، نمایه، مدل، Agent و سرویس شرط این milestone نیستند.

**نکتهٔ تعیین‌کننده:** کد فعلی از قبل ورودی یک‌باره و allowlist صریح **۱ تا ۲۰ فایل** دارد. بنابراین «افزودن جست‌وجوی چندفایلی» یا «ساخت entry point» نباید به‌عنوان قابلیت جدید وعده داده شود. خلأ محتمل، تبدیل نتیجهٔ فنی به استفادهٔ تکرارپذیر و قابل‌فهم است؛ وجود این خلأ هنوز از کاربر اثبات نشده است.

ارزش مورد انتظار: کاربر بتواند بندِ مرتبط با یک محدودیت، نتیجهٔ آزمون یا نیاز پروژه را پیدا و همان نسخهٔ منبع را بررسی کند، بدون رونویسی دستی شمارهٔ خط و هش. مقدار زمان صرفه‌جویی یا منفعت مالی اندازه‌گیری نشده است. نمونهٔ کار: «بند مربوط به وضعیت UTF-8 در اسناد مجاز کجاست؟» با عبارت مشخص `UTF-8`؛ خروجی **شاهد بازیابی‌شده** است. تشخیص اینکه کدام یادداشت تاریخی superseded شده، همچنان به خواندن و تأیید انسانی نیاز دارد.

**معیار نقض توصیه:** اگر کاربر همین CLI را برای نیاز سندی فعلی کافی بداند، یا سؤال/استفادهٔ تکرارشونده‌ای از این جنس نداشته باشد، توسعهٔ CAP-006 متوقف شود. گام بعدی در این حالت:
1. اگر کار اصلی او پژوهش است: **پروندهٔ شواهد یک مقایسهٔ کوچک از دو متن رسمیِ مجاز**؛
2. اگر یک فایل داده و خروجی تحویلی مشخص دارد: **گزارش کنترل کیفیت/استخراج CSV** که می‌تواند فوراً رتبهٔ اول شود.

**یک سؤال تصمیم برای کاربر، پیش از ساخت:** «در استفادهٔ بعدی کدام خروجی واقعاً به کارت می‌آید: پیدا کردن بند از اسناد پروژه، مقایسهٔ مستند دو منبع فناوری، یا تحویل یک CSV بررسی‌شده؟» این سؤال داخل گزارش پیشنهاد شده است؛ هیچ اجرای بعدی از پاسخ پژوهشی مجاز نشده است.

## ۵. مسیر برگزیدهٔ پیشنهادی و طرح آزمون فقط روی کاغذ

### milestone قابل مشاهده

**«یک جست‌وجوی واقعی در نسخه‌های مجاز اسناد → یک گزارش شواهد خوانا و قابل‌بررسی»**؛ نه افزودن فرمت/مدل/مدیر. حداکثر ۳–۵ فایل در pilot پیشنهادی، زیر سقف‌های موجود. این تعداد صرفاً scope پیشنهادی است و نتیجهٔ تست چندفایلی واقعی نیست.

اجزای کمینه:
1. ورودی یک‌باره از کاربر: root و نام‌های relative دقیق، query و مقصد خروجی مجاز؛ بدون glob/scan/فهرست‌سازی خودکار از دستگاه یا GitHub/Notion.
2. موتور CAP-006 موجود با contract فعلی؛ خط اصلی و `match_mode` حفظ شود.
3. JSON معتبر و نمایش فارسیِ شواهد: فایل/خط/هش، تعداد فایل/نتیجه، `truncated` و هشدار relaxed-whitespace. نخست نمایش ساده کافی است؛ تولید TXT فقط اگر خروجی فایل بخشی از تأیید کاربر باشد.
4. کنترل انسانی: بازکردن منبع مربوط، تشخیص historical/current و قبول/رد ارتباط نتیجه. هیچ پاسخ معنایی یا «همهٔ منابع بررسی شد» از `succeeded` استنباط نشود.

**قرارداد قابل reuse:** همان `contract_version/task_id/capability/permission_scope/status/searched/matches/error` حفظ شود. `task_id` فعلی fingerprint ورودی/محتواست و همهٔ خصوصیات اجرای هر بار را پوشش نمی‌دهد؛ آن را unique run ID یا ledger ننامید. اگر گزارش زمان اجرا/نسخه می‌خواهد، metadata نمایشیِ همان خروجی است؛ نیازی به registry/state machine/DB جدید نیست. Viewer فقط Projection است و حق تغییر permission یا متن اصلی ندارد.

### منابع، هزینه و حریم خصوصی در pilot

هیچ مدل، daemon، scheduler، cloud یا ابزار نصب‌نشده لازم نیست. CPU/RAM/commit/زمان تا خروجی و اثر روی foreground **UNKNOWN / MEASURE LATER** است؛ فقط اگر اجرای مجاز نشانهٔ کندی/فشار داشت مشاهدهٔ محدود همان workload لازم می‌شود، نه یک D0 کلی دیگر. سقف اندازهٔ فایل، RAM peak نیست. هیچ مشتری/credential در ورودی یا log نباشد و خروجی نیز به‌طور خودکار در GitHub/Notion بارگذاری نشود. offline پس از آماده‌بودن فایل‌ها ممکن است؛ هنگام خاموشی لپ‌تاپ اجرا وجود ندارد و این مورد استفاده نیاز always-on نشان نداده است.

### مرز گسترش آینده

Curator می‌تواند بعداً JSON شواهد را مصرف کند؛ formatter مستقل از موتور می‌ماند. برای persona فقط نام capability و permission روشن کافی است؛ برای observability فعلاً receipt و خطا کافی است. REQ-OBS-001، REQ-MPA-001 و REQ-TDR-001 همگی **DEFERRED** می‌مانند؛ نه telemetry، نه profile registry، نه polling/RSS/crawler در این milestone ساخته شود.
