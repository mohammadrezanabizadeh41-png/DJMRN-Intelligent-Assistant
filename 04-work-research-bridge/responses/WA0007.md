## S4 — Search playbook قابل استفاده در مرحلهٔ بعد

queryهای S3 نمونهٔ دقیقِ پیشنهادی‌اند؛ جز موارد تصریح‌شده در رسید، اجرای همه آن‌ها ادعا نمی‌شود. این تفکیک مانع تبدیل برنامهٔ آینده به یافتهٔ انجام‌شده است.

| نقش A–H | queryهای بعدی؛ انگلیسی / فارسی / چینی | مسیر و فیلتر |
|---|---|---|
| A برنامه کامل | `local chat application custom tools Windows`؛ `دستیار محلی مکالمه ابزار سفارشی ویندوز`؛ `开源 Windows 桌面 助手 自定义工具` | S27/S04 برای app-first سپس S01؛ release Windows و اصل repo؛ صرف عبارت AI assistant کافی نیست |
| B starter | `minimal conversational UI tool calling open source`؛ `نمونه رابط گفت‌وگو فراخوانی ابزار`؛ `聊天 工具调用 示例 项目` | S13/S16/S14؛ جداگانه Python، C#، Go، Rust، TypeScript؛ starter و full app جدا |
| C trusted bridge | `typed tool adapter approval scope stdio`؛ `تأیید انسانی ابزار فقط خواندنی`؛ `工具调用 权限 审批 只读` | S11/S05–09/S01؛ جست‌وجوی gate بیرون مدل؛ stdio مساوی isolation نیست |
| D provenance | `local file search line numbers citations`؛ `جست‌وجوی فایل شماره خط منبع`؛ `本地 文档 搜索 引用 行号` | S03/S08/S14/S16؛ متن ساده/FTS را هم جست‌وجو کن؛ embedding اجباری نیست |
| E inference | `Persian small model tool calling model card`؛ `مدل کوچک فارسی فراخوانی تابع`؛ `小模型 工具调用 波斯语` | S10/S22؛ وزن، tokenizer/template، engine و benchmark جدا؛ Windows architecture از RAM جدا |
| F workflow | `chat document human approval template`؛ `الگوی گفتگو تأیید انسان جستجوی سند`؛ `聊天 文档 人工审批 工作流` | S24/S25/S26؛ فقط طرح فرایند؛ engine/import/credential اجرا نشود |
| G built-in/hosted | `Windows official local AI content search sample`؛ `ChatGPT connector local MCP official support` | S14/S15/S29 و docs رسمی ناشر؛ plan/client/region جدا؛ وضعیت Plus custom MCP فرض نشود |
| H tests/signals | `tool calling permission boundary benchmark source code`؛ `آزمون استناد و امتناع ابزار` | S22/S19/S20/S29؛ خبر→اصل repo→release/test؛ خوداظهاری paper فقط hypothesis |

بهینه‌سازی per-hub:
1. **GitHub** repository search با عبارت‌های کوتاه جدا، سپس `language:Python` / `language:C#` / `language:Go` / `language:Rust` / `language:TypeScript`، `archived:false` و تاریخ `pushed:>=2026-07-01`. تاریخ فیلتر اکتشافی است؛ نسخهٔ قدیمی پایدار را خودکار حذف نکن. ابتدا metadata search؛ پس از شناخت repo، جست‌وجوی `approval` / `read_only` / `stdio` در کد با شاخص مناسب و محدودیتش. topic user-curated و Trending مکمل‌اند. forkها معمولاً در repository search عادی پنهان‌اند؛ در صورت نیاز جدا جست‌وجو شوند. Issues/Discussions فقط شاهد سؤال/گزارش؛ پاسخ maintainer و release را تفکیک کن.
2. **GitLab** Explore name/topic/language؛ اگر rendered results خوانده نشد `site:gitlab.com assistant tool calling Windows` فقط lead است، سپس public repo و tag را باز کن. query مسدود را نتیجهٔ صفر ثبت نکن.
3. **کاتالوگ‌ها** category/OS/license سپس visit official website/repository؛ از صفحهٔ اصلی به فهرست واقعی برو. Sponsored، affiliate و closed source را با OSS یکسان نکن. S23 صرفاً اجزای UI می‌دهد.
4. **رجیستری‌ها** عبارت کوتاهِ نقش، نه پرسش بلند طبیعی. package ID/namespace، نسخه، repository_url، tag، maintenance/yank را ثبت کن؛ لینک repository بدون تطابق author/version کافی نیست. NuGet TFM و prerelease؛ Go نام/symbol؛ crates query متن؛ PyPI classifier؛ npm keyword/last-published. هیچ install برای کشف لازم نیست.
5. **HF/MCP/skills** HF full-text و نوع artifact را انتخاب کن؛ Space→Files→revision و کارت مدل→license/قالب. MCP metadata→package/source→version؛ skills→SKILL.md/upstream؛ فایل دستور خارجی حق اجرای خودش را ایجاد نمی‌کند.
6. **گالری رسمی** پوشهٔ نمونه و dependencies را به نسخه pin کن؛ UI confirmation را از enforcement واقعی scope جدا کن. Cloud-only نمونه، بی‌ارزش نیست ولی end-to-end local M1 هم نیست.
7. **خوراک و paper** تاریخ انتشار و نسخهٔ مقاله/announcement را ثبت کن؛ خبر→upstream→کد آزمون. popular today یا رقم benchmark آزمایش مستقل نیست.
8. **metadata** S21 برای یافتن alias/manifest/registry و بررسی تأخیر sync؛ منبع تکراری و mirror را با canonical repo_id/package namespace یکی کن.

قالب پروندهٔ reproducible برای **WQ جداگانهٔ بعدی**: `source_id, query, searched_at, result_url, canonical_owner/repo_id, artifact_role, branch/tag, full_commit_sha, path/blob_sha, package_name/version/digest, model_revision, license_file_at_revision, claim→evidence, tested/documented/unknown, access/cost/region, duplicate_of, unresolved_questions`. برای کد line link همان commit؛ برای package digest و نسخه؛ برای وزن HF revision؛ برای workflow مسیر JSON و engine version. branch متحرک و عبارت latest تنها مرجع کافی نیست. اگر docs/README با release فرق داشت، اختلاف با تاریخ‌ها نگه داشته شود؛ بی‌صدا یکی انتخاب نشود.

## S8 — توقف و تحویل

**Stage 1 complete در دامنهٔ source map با access gaps مستند**: سه receipt واقعی + merged source matrix، ۲۹ endpoint/کانال بدون padding mirror، ۸ خانواده، ۲۱ مشاهدهٔ M و ۸ D، playbook چندزبانه، پوشش A–H، سه مثال UNVETTED، مسیر ده‌کاناله و بودجهٔ واقع‌بینانه فراهم شد. این نتیجه به معنی ۲۹ query بومی موفق یا کشف همه منابع جهان نیست. محدودیت اصلی: forgeهای جایگزین/extension registries، queryهای JS/403/blocked، ناشر بعضی nicheها، region/account/freequota و قابلیت واقعی محصولات.

**STAGE2_NOT_RUN / STAGE3_NOT_RUN.** نه inventory عمیق ۱۵–۳۰ محصول، نه انتخاب host/model/stack، نه ADOPT/BUILD، نه کد/نصب/اجرای مدل یا pilot، نه WQ0008، نه تغییر معماری/حافظه/Notion/Windows/حساب انجام شد. هیچ source subscription یا Radar موازی ایجاد نشده است.

پیشنهاد به هماهنگ‌کننده: ابتدا receipt و تمایز M/D، هویت‌ها و کفایت پوشش را مستقل review کند؛ پس از تأیید کاربر WQ متمایز Stage2 با ده مسیر، artifact roles و سقف اطلاعات بالا بنویسد. Stage3 تنها بعد از review Stage2 باید چند گزینهٔ دارای شواهد کافی را از نظر قابلیت، adaptation burden و ساخت ساده مقایسه کند. unresolved access gaps می‌توانند هدف محدود مرحلهٔ بعد باشند؛ مجوز blanket install یا تکرار پژوهش قبلی نیستند.

### ثبت و طرح بازخوانی مستقل
