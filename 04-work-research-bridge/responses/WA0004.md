## 1. روش و قرارداد شواهد

زنجیرهٔ کار: **نیاز کاربر → A کتابخانه → B وضعیت واقعی پروژه → C کشف مستقل → هویت یکتا → اصل مدرک → نقد → ارزش مشروط**. مرحلهٔ C با پرسش‌های دسته/نقش شروع شد، پیش از بستن shortlist به نام‌های قبلی. سپس نام/URL/مالک/alias با متن زندهٔ دو catalog و منابع مرتبط پروژه تطبیق داده شد.

- **FACT / RESEARCH VERIFIED:** محتوای منبع اولیه واقعاً دریافت شده؛ دامنهٔ ادعا فقط همان مشاهده است.
- **PUBLISHED CLAIM:** نویسنده چنین گفته؛ کیفیت/سرعت/امنیت را ما اجرا یا مستقل بازتولید نکرده‌ایم.
- **PROJECT-HISTORICAL:** شاهد قبلی پروژه/Notion با تاریخ؛ اثبات نسخهٔ امروز نیست.
- **INFERENCE/PROPOSAL:** داوری این گزارش، قابل رد و فاقد اختیار اجرا.
- **UNKNOWN/BLOCKED:** داده/مجوز/هزینه/دسترسی لازم موجود نیست.

شماره‌های E در این گزارش فقط ارجاع داخلی‌اند؛ SRC/KB/TECH یا task جدید نیستند. مرور issue/PR/آخرین workflow نمونه‌برداری محدود است؛ سبز بودن یک workflow، گواه امنیت/کیفیت کل پروژه نیست. metadata شاخهٔ main و release جدا بررسی شدند؛ **شمارهٔ package، tag release، tree SHA و commit SHA یکسان فرض نشده‌اند.**

### 2.4 شش منبع هستهٔ پیشنهادی و روش کم‌نویز

**شش ورودی P0**: GitHub Search+اصل/release، HF Hub، HN/Show HN، arXiv موضوعی، PyPI RSS محدود، allowlist کوچک releaseهای رسمی. این‌ها شش *نوع ورودی* هستند، نه شش سرویس جدید لازم برای ساخت. P1ها به‌صورت چرخشی gaps چین، forge مستقل، رسانه و registryهای دیگر را پوشش دهند؛ P2ها دستی/موردی.

امتیاز P0 با وجود رابط مستند، ارزش complementary و امکان نمونه‌گیری محدود توجیه شده؛ بازده/precision آن اندازه‌گیری نشده. اگر source به‌ازای بودجهٔ مرور، lead مفید کافی ندهد، باید پایین بیاید؛ معروف‌بودن حق ماندن نمی‌دهد.

نمونهٔ **query پیشنهادی آینده، نه ادعای اجرای این URLها در این دور**:
- `topic:document-understanding created:>=2026-07-23 archived:false fork:false`
- `topic:video-editor pushed:>=2026-09-21 language:TypeScript archived:false`
- `sandbox in:name,description,readme language:Rust stars:>20`
- چرخش واژه‌های native مانند `工作流`، `模型推理` و جست‌وجوی role، بدون تحمیل language/star floor به همهٔ دسته‌ها.

created فقط تاریخ این repository است؛ پروژهٔ منتقل‌شده ممکن است قدیمی باشد. pushed با updated و release فرق دارد. fork=false بعضی forkهای ارزشمند را حذف می‌کند؛ یک مسیر fork/rename جدا لازم است. نتایج bounded/paginated، index ناقص و حذف پروژهٔ کم‌star سوگیری می‌آورند. تعداد star یک لحظه velocity نیست؛ growth فقط با دو snapshot هم‌دامنه و timestamp معتبر محاسبه شود. Awesome list فقط lead است. release cadence همراه با test/issue/maintainer و رویداد واقعی بررسی شود؛ frequent bot dependency bumps ارزش محصول را ثابت نمی‌کنند.
