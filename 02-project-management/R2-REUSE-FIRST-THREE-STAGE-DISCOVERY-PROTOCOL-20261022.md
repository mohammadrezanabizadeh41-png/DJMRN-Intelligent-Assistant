## Why and exactly what is in scope

Before writing a new DJMRN chat host, bridge, permissions core or small assistant, actively look for reusable complete applications, developer starters, public source code, package libraries, templates, MCP tool adapters, local chat UIs, direct model/tool-calling shells, security/approval components and documented combinations that already solve **one constrained M1 request**. Python, Go, C#/.NET, Rust, TypeScript/JavaScript, cross-platform desktop/browser or lawful hosted solutions are eligible. Jan is a candidate, not the default winner. A bare LLM weight checkpoint is **not** a chat host/tool app. A package is **not** necessarily a turnkey app; a workflow JSON is **not** proof of an installed runtime. No requirement to find a multi-agent platform for one tool call.

**Fixed M1 scenario:** user sends a natural-language Persian message from a local chat surface, a trusted tool permission boundary allows only 1–2 authorized Markdown files, CAP-006 or an equivalent source-grounded search executes, user receives factual Persian response with file/line, or fail-closed error. Tool/model host and Windows hardware specifics remain testing questions. Future local+eligible ChatGPT dual-surface, Gmail/freelance U2 and logical specialist U3 are *fit/extensibility dimensions*, not reasons to broaden Stage 1 to a global agent market survey.
