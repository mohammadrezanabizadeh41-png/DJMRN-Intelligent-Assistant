## هدف محدود

آزمایش اینکه آیا بدون نصب Agent، بدون مدل و بدون اتصال Gmail می‌توان دسته‌بندی اولیهٔ فرصت‌ها و پیگیری‌های کاری، ترجیح متن کامل‌تر اعلان سایت نسبت به خلاصهٔ ایمیل، ادغام اعلان تکراری و گزارش فارسی قابل ردگیری را انجام داد.

**این نمونه فقط یک مسیر از سه مسیر را واقعاً آزموده است؛ «مقایسهٔ کامل سه محصول» هنوز انجام نشده است.** هیچ محصول ثالثی روی سیستم کاربر نصب نشده، هیچ Gmail، IMAP، API، کوکی، سایت کاری، رمز یا دادهٔ شخصی خوانده نشده و قابلیت ارسال پیغام/ایمیل وجود ندارد. نشانی‌های `.example` ساختگی‌اند.

## اجرا (فقط پوشهٔ حاوی داده‌های ساختگی)

```powershell
python -m unittest -v test_mail_triage_v0.py
python mail_triage_v0.py
```

برنامه صرفاً فایل `synthetic_inbox.json` را از همان پوشه می‌خواند؛ بدون اینترنت یا وابستگی غیر استاندارد. خروجی نمونهٔ *واقعاً مشاهده‌شده* در `ACTUAL_SYNTHETIC_REPORT.md` نگهداری شده است. آزمون ویندوز کاربر **هنوز انجام نشده است**. اجرای کد شخص ثالث، اتصال Gmail و نصب روی Windows نیازمند مجوز/تست جداگانه است.

## ورودی و نتیجهٔ واقعی در محیط اجرای مدل

- ۲۰ ایمیل کاملاً ساختگی + ۶ فرصت ساختگی پنل سایت = ۲۶ رکورد؛ کلید `offer_id` برای مثال‌ها از پیش تعیین شده است.
- ۴ اعلان ایمیلی و پنل سایت برای یک فرصت مشترک بودند؛ ۲۲ کلید یکتا باقی ماند.
- خروجی منتخب پس از ادغام: ۸ مورد `OPPORTUNITY_REVIEW`، ۴ `FOLLOW_UP`، ۴ `OTHER`، ۴ `BLOCKED_OR_VERIFY` و ۲ `NEEDS_REVIEW`.
- ۷ آزمون `unittest` روی **Linux container, Python 3.13.5** با نتیجه `OK`؛ این امتیاز ۷/۷ روی fixture طراحی‌شده توسط همان نویسنده، **درستی واقعی/آزمون عملیاتی حساب‌های کاربری نیست**.
- دسته‌بندی و بودجه فقط بر اساس رشته‌های متن و قواعد ساده انجام می‌شود؛ «BLOCKED_OR_VERIFY» داوری حقوقی قطعی نیست. دستورهای تزریق‌شدهٔ داخل متن فقط علامت‌گذاری می‌شوند.

## محدودیت‌های مهم

- قالب دادهٔ تست متن ایمیل و اعلان را دارد، ولی **MIME، پیوست، رشتهٔ مکاتبهٔ چندپیامی واقعی، pagination و OAuth/Session ندارد**؛ پس ادعای خواندن کامل Gmail اشتباه است.
- ادغام بر پایهٔ شناسهٔ قراردادی ساختگی است، نه تشخیص خودکار ایمیل و سایت واقعی.
- انتخاب اولین رکورد `portal` هنگام وجود چند نسخه، به معنی مدیریت نسخه‌های زمانی یا تغییر بودجه در تولید نیست.
- بودجه فقط از `\$` عددی ساده استخراج می‌شود؛ ارقام فارسی، ارزها و شروط پیچیدهٔ قرارداد پشتیبانی نشده‌اند.
- هیچ مقایسهٔ CPU/RAM لپ‌تاپ انجام نشده و هیچ مدل فارسی/مرورگر واقعی ارزیابی نشده است.
- قواعد دسته‌بندی فقط یک baseline تعیین‌پذیر هستند؛ دقت در بازار یا inbox واقعی اثبات نشده است.

## خروجی‌های این بسته

`synthetic_inbox.json`: مثال‌های ساخته‌شده، `mail_triage_v0.py`: اجرای بی‌وابستگی، `test_mail_triage_v0.py`: آزمون‌های کنترل‌شده، `ACTUAL_SYNTHETIC_REPORT.md`: گزارش نمونهٔ واقعی، `EVIDENCE.md`: رسیدها و محدودیت‌های اثبات، `THREE-ROUTE-COMPARISON.md`: روش مقایسهٔ سه رویکرد.
