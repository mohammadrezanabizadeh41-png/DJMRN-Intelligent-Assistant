# راهنمای داده و پوشش

## تعریف دستهٔ رایگان

| Code | معنی |
|---|---|
| A | رایگان دائمیِ منتشرشده با محدودیت؛ دائمی بودن تضمین آینده نیست |
| B | سهمیهٔ روزانهٔ تجدیدشونده |
| C | سهمیهٔ ماهانهٔ تجدیدشونده |
| D | اعتبار دلاری/توکنی دوره‌ای |
| E | اعتبار اولیهٔ یک‌باره |
| F | شرط هویت، ایمیل، منطقه، مجوز یا تأیید |
| G | کمپین یا trial موقت |
| H | برنامهٔ توسعه‌دهنده/استارتاپ/پژوهش |
| I | واریز وجه شرط دریافت یا مصرف بونوس |

علامت `;` ترکیب چند ویژگی است، نه جمع دو سهمیه. Free_Amount، Reset، Signup_Credits و Expiry هم‌زمان خوانده شوند. UNKNOWN یعنی نبود مدرک کافی در این اجرای پژوهش؛ صفر یا پاسخ منفی نیست. مقدار Weighted_Score خالی است، نه صفر. تاریخ Last_Verified روز مشاهدهٔ مدرک عمومی است؛ هیچ API فراخوانی نشده است.

`ID` برای نامزدهای تازه، نام پیشنهادی پژوهش است. `Proposed_ID` نام اولیهٔ intake را نگه می‌دارد؛ برای موارد از قبل در ۳۷۵، ID با شناسهٔ canonical جایگزین شده است. `Broader_375_Match` وجود در کاتالوگ وسیع‌تر را مشخص می‌کند. `Review_Decision` همواره PENDING_USER_REVIEW است.

`Official_Website` نشانی شناخته‌شدهٔ خدمت است؛ تأیید ثبت حقوقی یا مالک نهایی نیست. `API_Docs` اگر پیدا نشده UNKNOWN می‌ماند؛ بعضی نشانی‌ها landing API/pricing هستند و schema کامل endpoint ندارند. `API_Compatibility` تنها ادعای مستند عمومی است. `Gateway_Fit` ارزیابی فنی اولیه است و مجوز قرارداد یا تست integration نیست.

`Evidence_Refs` به `03-SOURCE-MANIFEST.csv` وصل می‌شود. همان فایل URL و نوع مشاهده SEARCH_EXCERPT، OPEN یا FIND و خطای دریافت را نگه می‌دارد. OPEN موفق نیز تنها محتوای متن بازیابی‌شدهٔ همان صفحه است، نه مطالعهٔ تمام سایت. source manifest شامل سرنخ‌های جست‌وجو است؛ تمام URLهای آن منبع تأییدشدهٔ یک یافته نیستند. وب‌سایت رسمی فقط برای رکوردهای مرتبط و با شرط یادشده مرجع تأیید است. اختلاف claimهای رسمی در Notes/Evidence_Status ثبت شده است.

## پوشش فنی

LLM، reasoning و coding عمدتاً در router/hosted model API بررسی شدند. embedding/reranking با Pinecone/Contextual/Isaacus، اسناد و OCR با چندین سرویس، صدا با RTZR/Murf/Hume و سرویس‌های شناخته‌شده، ترجمه با DeepL/Lingvanex، تصویر/ویدیو با Runware/Bria/Vidu/deAPI/MagicHour/Tavus، و search/retrieval با Exa/Tavily/Parallel/You پوشش داده شد. این چهار search provider از قبل در ۳۷۵ بودند و کشف تازه نیستند. مدل‌های تخصصی و منطقه‌ای همچنان مسیر ادامه‌اند.

برای تطبیق ماشینی، `04-IDENTITY-MATCH-AUDIT-80.csv` exact ID، دامنه با subdomain و نام/alias نرمال‌شده را با تمام ۳۷۵ رکورد مقایسه می‌کند. این ابزار فقط قرینه است؛ Notes تصمیم هویتی عمومی را توضیح می‌دهد. عدم تطبیق ماشینی به‌تنهایی اثبات شرکت مستقل نیست.
