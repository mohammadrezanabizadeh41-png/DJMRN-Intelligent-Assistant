## Reuse pathways independently sourced
1. **Preferred no additional model download:** KYNXA `v1.7.0` implementation [LocalModelsPage.Actions.cs](https://github.com/jinpeng900/KYNXA/blob/v1.7.0/apps/desktop/Views/LocalModelsPage.Actions.cs) exposes `Import GGUF` and a checkbox **"Copy to model folder (if unchecked, reference original file)"**. File picker selects existing .gguf; import stores an external-reference instead of duplicating when unchecked, then model must still be enabled manually. Existing `Gemma 3 1B Q4_0` GGUF recorded under Jan is lightest suitable existing test candidate. A reference path might break if Jan/cache moves/cleans it; original file must remain in place. This source code presence is not a successful KYNXA runtime import test. **No file was imported/modified in this turn.**
2. **Alternative:** Jan Desktop official Local API Server https://docs.jan.ai/desktop/api-server serves existing Jan local models via OpenAI-compatible `http://127.0.0.1:1337/v1` when the server is started. KYNXA v1.7 [ModelPresets.cs](https://github.com/jinpeng900/KYNXA/blob/v1.7.0/apps/desktop/Services/Models/ModelPresets.cs) lists `local-api` default `127.0.0.1:8080/v1`, accepts user-supplied local endpoint; KYNXA translations explain direct API does not require Ollama. Thus the Jan port must explicitly be overridden to **1337** if used. Running both GUIs/engines may consume more RAM; Jan local-model local API needs explicit activation by user and is not guaranteed on their specific installed version.
3. **Ollama path not first:** zero models previously listed; linking Jan GGUF via new Ollama import creates separate setup and may duplicate model storage. LM Studio recorded Gemma 4 E4B stalled previously.
